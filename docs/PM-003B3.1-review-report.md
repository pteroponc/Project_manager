## Выполнено

Добавлены два маршрута:

- POST `/api/projects/{id}/architecture`: `expectedProjectVersion`, обязательные
  `criticality`, `stage`, `solutionType`, необязательные реквизиты/наборы; 201 с полным DTO.
- PATCH `/api/projects/{id}/architecture`: `expectedVersion` паспорта и минимум одно
  изменяемое поле; 200 с полным DTO.

Пропущенные PATCH-поля сохраняются; null очищает только nullable-реквизит. Переданный
массив полностью заменяет набор, пустой массив очищает его; null, дубликаты и неизвестные
коды запрещены. Черновик разрешён. Компоненты, интеграции, риски и проверки не создаются.

POST использует общий ProjectWriteLock до проверки паспорта/версии и записи. Новый паспорт
получает версию 0, проект увеличивается на 1 в той же транзакции. PATCH блокирует строку
паспорта и меняет только его версию, ровно на 1, включая прежние значения. При обычном
изменении работает @Version, при чистом PATCH с фиксированным Clock — CAS и refresh.
В конфликтах возвращаются реальные currentVersion и versionResource=PROJECT|PASSPORT.

createdAt/updatedAt задаются серверным Clock в UTC; PATCH сохраняет createdAt.
Поля и оба набора атомарны. После flush используется общий сборщик B2.2 внутри той же
write-транзакции через cardAfterWrite/Propagation.MANDATORY. Ответ включает все причины,
версии и оценку без изменения формулы. Бюджет не возвращается.
Существующие GET остаются read-only REPEATABLE_READ; тесты B2.2 прошли полностью.

JSON-разбор новых маршрутов отделён от старых API: закрытые поля, строгие типы,
отказ при дубликатах/лишнем JSON, тело максимум 32 KiB, массивы максимум 6/5.
Текст обрезается по краям, нормализуется NFC, длина проверяется после нормализации;
сохраняются строки управленческих описаний, CRLF/CR приводится к LF.
Пустые строки, запрещённые управляющие/FORMAT-символы, HTML/исполняемые фрагменты,
явные секреты/URL/IP/строки подключения отклоняются без отражения исходного значения.
Новое логирование запросов, полей или обоснований не добавлено; клиентские ошибки не
раскрывают SQL, stack trace, пути или Java-классы.

Подробный контракт, каталоги, размеры, транзакционные шаги и ошибки:
`docs/PM-003B3.1-passport-write-api.md`.

### Конкурентные сценарии

| Сценарий | Подтверждённый результат |
|---|---|
| Первый POST удерживает project lock, второй POST ждёт | Первый HTTP 201, второй HTTP 409 PASSPORT_ALREADY_EXISTS; один паспорт version=0, project version=1; currentVersion=0/PASSPORT |
| Первый PATCH удерживает passport lock, второй с той же версией ждёт | Первый HTTP 200, второй HTTP 409 PASSPORT_VERSION_CONFLICT; сохраняется Winner, паспорт version=1, project version=1; currentVersion=1/PASSPORT |
| POST паспорта удерживает project lock, DELETE ждёт | POST 201, DELETE HTTP 409 PROJECT_HAS_DEPENDENCIES; проект, паспорт и наборы сохраняются; сирот нет |
| DELETE проекта удерживает project lock, POST ждёт | После commit DELETE: POST HTTP 404 PROJECT_NOT_FOUND; целевой проект и паспорт отсутствуют, сирот нет |

Первая транзакция удерживается CountDownLatch после записи и до commit.
Вторая выполняет реальный запрос на отдельном соединении. До освобождения первой
`INFORMATION_SCHEMA.SESSIONS` должна показать BLOCKED, реальный BLOCKER_ID и SQL
ожидаемой таблицы; одновременно проверяется `Future.isDone()==false`.
Только после этого барьер отпускается и проверяются результат и данные.
Короткое ожидание в цикле служит опросу фактического состояния H2; исход теста не
зависит от случайной задержки старта запроса. Проверены сироты паспорта и обоих наборов.
Существующий DELETE не расширялся: в первом порядке после общей сериализации его
удалению препятствует уже существующий FK паспорта NO ACTION.

На этапе настройки исправлены тестовые проблемы: mock Clock возвращал null при
конструировании оценщика с withZone; заменён на реальный управляемый Clock через
тестовую подмену бина. Сравнение DTO/JSON учитывает одинаковую сериализацию числовых
узлов Jackson. Финальные конкурентные проверки прошли и в первом полном прогоне,
и в окончательном полном прогоне после дополнения фильтра явных секретов.

## Примеры

POST черновика:

```json
{"expectedProjectVersion":0,"criticality":"HIGH","stage":"NOT_STARTED","solutionType":"NEW_SOLUTION","dataClasses":[],"environments":[]}
```

Ответ 201 — полный агрегат B2.2. Основные значения: project.version=1,
passport.version=0, createdAt=updatedAt=серверный UTC-момент, все коллекции пусты,
assessment.status=NOT_ASSESSED, officialGoLiveApproval=false; все причины расчёта сохранены.

PATCH nullable-поля и набора:

```json
{"expectedVersion":0,"architect":null,"dataClasses":["PERSONAL"],"environments":[]}
```

Ответ 200 — полный агрегат: passport.version=1, architect=null,
dataClasses=["PERSONAL"], environments=[], пропущенные реквизиты сохранены,
project.version прежняя, createdAt прежний, updatedAt серверный UTC-момент.

409 паспорта:

```json
{"code":"PASSPORT_VERSION_CONFLICT","error":"Version does not match","currentVersion":1,"versionResource":"PASSPORT"}
```

409 проекта при POST:

```json
{"code":"PROJECT_VERSION_CONFLICT","error":"Version does not match","currentVersion":5,"versionResource":"PROJECT"}
```

Неверный набор:

```json
{"code":"VALIDATION_ERROR","error":"Invalid passport fields","fieldErrors":{"dataClasses":"Invalid value"}}
```
