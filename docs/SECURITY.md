DEC-023–029 и PRIV-001 обязательны. Только демонстрационный пилот, синтетические данные. Запрещена самостоятельная передача идей, кода, документации, персональных данных внешним сервисам, моделям, агентам или третьим лицам. Пользователь сам передаёт материалы Codex. Не передавать секреты, не включать их в отчёты. Внешние и необратимые действия, публикация, доступы, расходы — только явное разрешение.

Ассистент: требования, архитектура, техническое ревью ИБ. Codex: безопасная реализация и тестирование. Владелец: продуктовая приёмка, разрешения; не security review. Абсолютная безопасность не гарантируется.

Перед публикацией документации в удалённом Git-репозитории проверить его приватность, доступы, сторонние приложения и историю на секреты; внешняя проверка не проведена. Не публиковать до разрешения. Сохранять существующую защиту публичного пилота. ИИ — отдельное решение о передаче данных, prompt injection, валидации и подтверждении изменений.

Не путать безопасность самого пилота с управленческим контролем требований ИБ демонстрационных проектов (DEC-030).


## Локальная документация и разрешения — DEC-032–035

При любом сомнении в безопасности или полномочиях до решения/зависимой задачи обратиться к владельцу по формату [PROJECT_GOVERNANCE.md](PROJECT_GOVERNANCE.md). Не переспрашивать однозначно согласованное и не ослаблять режим без явного решения.

Локальное размещение docs/ не является публикацией. Commit и push требуют отдельных разрешений. До commit проверить содержимое документации и точный staged diff, исключить секреты/персональные данные/посторонние файлы. В PM-DOC-001.3D staging, commit и push были запрещены; отдельное задание PM-DOC-001.3D.2 разрешает staging ровно13 согласованных файлов и один локальный commit после проверки. Push и сетевые операции не разрешены.

До будущего push отдельно проверить приватность репозитория, доступы, подключённые приложения, историю на секреты, GitHub Actions и deployment-артефакты. Эти внешние проверки сейчас не выполнены; прямой доступ ассистента к GitHub не подключается. Владелец передаёт необходимые diff и доказательства, но технический security review не становится его обязанностью.

Не допускать конфиденциальные документы в публичные артефакты, Pages или demo-сборки. При анализе учитывать checkout репозитория runner-ом, исходные архивы Git/GitHub и доступы интеграций, а не только JAR. Крупные review-архивы хранить вне Git. Передаваемые материалы проверять на секреты и персональные данные; реальные пароли/ключи/credentials сюда не помещаются.

Сохранять существующие механизмы изоляции и защиты пилота. Размещение документации не меняет workflows, сборку, deployment или security-конфигурацию и не означает нового server audit.
