## Реализация

В разделах компонентов и интеграций доступны добавление и редактирование.
Добавление показывается только при наличии паспорта. Выбор записи выполняется
по UUID, поиск по позиции в массиве не используется. В заголовке редактора —
название выбранной записи; UUID, технические версии и instanceId не выводятся
пользователю. UUID присутствует только в служебном атрибуте кнопки и адресе запроса.

Компонент: название, тип, назначение, платформа, критичность, внешний компонент,
порядок. Интеграция: название, источник, получатель, направление, взаимодействие,
аутентификация, критичность, готовность, классы данных, ответственная сторона,
комментарий. Использованы каталоги и длины действующего API. Назначение и
комментарий допускают многострочный текст. Перед отправкой текст обрезается
по краям и нормализуется NFC; фактический ввод остаётся в форме при ошибке.
Окончательную проверку текста и бизнес-правил выполняет существующий backend.

Общий редактор C.3a теперь принимает адаптер полей дочерней записи. Его оболочка,
защита навигации, диалог потери ввода, обработка ошибок и запоздалых ответов
переиспользуются. Одновременно открыт один редактор. Существующие стили сохранены,
CSS и дизайн приложения не менялись.

### Запросы

Все записи отправляются с `Content-Type: application/json`.

POST `/api/projects/{id}/architecture/components`:

```json
{
  "expectedPassportVersion": 981238,
  "expectedPassportInstanceId": "f071002a-3da5-4bc6-b472-6ba147514ea2",
  "name": "Новый компонент",
  "componentType": "BACKEND",
  "criticality": "HIGH",
  "externalComponent": false,
  "position": 0
}
```

POST `/api/projects/{id}/architecture/integrations`:

```json
{
  "expectedPassportVersion": 981238,
  "expectedPassportInstanceId": "f071002a-3da5-4bc6-b472-6ba147514ea2",
  "name": "Обмен отчётами",
  "sourceSystem": "Учёт обращений",
  "targetSystem": "Отчётность",
  "direction": "OUTBOUND",
  "interactionType": "FILE_EXCHANGE",
  "authCategory": "SERVICE_ACCOUNT",
  "criticality": "LOW",
  "readiness": "PLANNED",
  "dataClasses": ["INTERNAL"]
}
```

Числа и UUID в примерах — из тестовых данных. В рабочей форме токены фиксируются
при открытии из исходного агрегата. Пустые nullable-поля POST пропускаются.

PATCH `/api/projects/{id}/architecture/components/{recordId}` при очистке
nullable-полей и изменении внешнего признака/порядка:

```json
{
  "expectedVersion": 12,
  "purpose": null,
  "platform": null,
  "externalComponent": false,
  "position": 0
}
```

PATCH `/api/projects/{id}/architecture/integrations/{recordId}`:

```json
{
  "expectedVersion": 17,
  "dataClasses": ["PUBLIC"],
  "responsibleParty": null,
  "comment": null
}
```

PATCH не содержит версии или instanceId паспорта. Версия — только выбранной
записи. Отправляются лишь изменённые поля; без изменений запроса нет.
`false` и `0` сохраняются как значения. Набор интеграции заменяется целиком,
сравнивается без учёта порядка и не может быть пустым. Технические версии
новых записей, ID и вычисленные значения клиент не назначает.

После успеха применяется полный агрегат ответа: сведения, коллекции и серверная
оценка. Дополнительный GET не выполняется, готовность в браузере не рассчитывается.
Пользовательская версия паспорта по-прежнему отображается из documentVersion.

### Ошибки и конкурентные изменения

- Ошибки 400: безопасные сообщения рядом с известными полями, весь ввод сохраняется.
- 409: ввод сохраняется, повторная запись из этой формы блокируется. Сверка
  загружает актуальный агрегат явно, не меняя исходную версию и instanceId.
- `PASSPORT_INSTANCE_CONFLICT` объясняет удаление и повторное создание паспорта.
  Сверка также сравнивает instanceId — это работает и после 404 старой дочерней записи.
- `COMPONENT_NOT_FOUND` / `INTEGRATION_NOT_FOUND` явно сообщают об удалённой записи.
  Отсутствующие проект/паспорт обрабатываются отдельно от конфликта версии.
- Сверка показывает актуальные поля и сохранённый ввод. Для новой записи
  не выдаёт значения по умолчанию за существующий объект сервера.
- Кнопка открытия актуального агрегата требует подтверждения потери черновика;
  автоматического переноса правок или замены токенов нет.
- Сетевая ошибка, 5xx или непригодный успешный ответ означают неизвестный результат:
  сервер мог выполнить запись. Автоматического повторения POST/PATCH нет.
- Двойное нажатие отправляет один запрос. Поля блокируются на время отправки.
- Закрытие, переходы между редакторами, карточками и разделами, история браузера
  и beforeunload используют общую защиту C.3a.
- Ответ старой формы не меняет новую форму; ответ старой записи/чтения не заменяет
  другой проект или более свежий снимок того же проекта.
- Текст выводится через textContent либо HTML-экранирование, включая сравнение.
