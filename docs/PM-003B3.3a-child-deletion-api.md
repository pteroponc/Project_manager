# PM-003B3.3a — удаление дочерних записей

## Четыре явных backend-маршрута

```text
DELETE /api/projects/{id}/architecture/components/{recordId}
DELETE /api/projects/{id}/architecture/integrations/{recordId}
DELETE /api/projects/{id}/architecture/checks/{recordId}
DELETE /api/projects/{id}/architecture/risks/{recordId}
```

У каждого три обязательных query-параметра:

| Параметр | Значение |
|---|---|
| expectedVersion | Техническая версия удаляемой записи |
| expectedPassportVersion | Техническая версия паспорта |
| confirmed | Точная строка `true`, явное подтверждение |

```text
DELETE /api/projects/p/architecture/integrations/record-id?expectedVersion=3&expectedPassportVersion=7&confirmed=true
```

Версии — неотрицательные десятичные целые 0…Long.MAX_VALUE−1; знаки, пробелы,
ведущие нули кроме `0`, дробные/экспоненциальные формы не принимаются. Параметры
должны быть одиночными: повторяющиеся, неизвестные, отсутствующие и некорректные
значения отклоняются с 400. `TRUE`, `false`, `1`, пустая строка не подтверждают удаление.
JSON-тело не является командой удаления и не заменяет query-параметры.
API не принимает произвольное имя коллекции: каждому пути соответствует отдельный метод.

## Транзакция и версии

В одной сервисной write-транзакции:

1. Проверить параметры без записей.
2. Общий `ProjectWriteLock` на проект; отсутствие — PROJECT_NOT_FOUND.
3. PESSIMISTIC_WRITE на паспорт; отсутствие — PASSPORT_NOT_FOUND.
4. PESSIMISTIC_WRITE на целевую запись с условием её принадлежности проекту.
   Чужая запись и отсутствующая дают одинаковый 404 без currentVersion.
5. После всех locks сравнить обе актуальные технические версии до первой записи.
   Если обе устарели, приоритет у версии паспорта.
6. Для интеграции явно удалить **только её** строки `project_integration_data_classes`
   через существующий class writer с пустым набором; flush. Затем удалить интеграцию.
   У остальных типов удалить только выбранную запись. Flush фактического удаления.
7. Атомарно увеличить техническую версию паспорта ровно на 1, refresh/flush.
8. Через `cardAfterWrite` с MANDATORY собрать полный архитектурный DTO и оценку B2
   внутри этой же транзакции. Успех — **200**, без последующего GET после commit.

Версия проекта, даты паспорта createdAt/updatedAt, пользовательская
documentVersion=1.0 не меняются. Никаких автоматических повторов при конфликте.
Повторный DELETE той же отсутствующей записи — 404, даже со старой версией паспорта.
FK NO ACTION, отсутствие CascadeType.REMOVE/orphanRemoval сохранены.
Все изменения, включая классификацию и счётчик паспорта, откатываются при ошибке
на любом шаге, в том числе после flush и при сборке ответа.

## Конкурентные операции

POST дочерних записей/initialize и DELETE используют общий порядок locks
проект → паспорт; DELETE затем блокирует запись. PATCH существующей записи
блокирует только эту строку и сохраняет независимость других записей.

| Порядок при одинаковых исходных версиях | Результат |
|---|---|
| Два DELETE одной записи | Первый 200, второй после ожидания 404 |
| DELETE разных записей, одна версия паспорта | Первый 200, второй 409 PASSPORT_VERSION_CONFLICT; вторая запись сохраняется |
| PATCH первым, DELETE вторым | PATCH 200 и версия записи +1; DELETE после ожидания 409 версии записи, изменение не теряется |
| DELETE первым, PATCH вторым | DELETE 200; PATCH после ожидания 404, восстановления строки нет |
| DELETE первым, POST вторым | DELETE 200; POST после ожидания 409 версии паспорта |
| POST первым, DELETE вторым | POST 201; DELETE после ожидания 409 версии паспорта, существующая запись сохраняется |

## Готовность, чтение и безопасность

Удалённая проверка не создаётся заново при GET. Удаление из завершённого набора
даёт неполноту и причины CHECK_TYPE_MISSING/CHECKS_INCOMPLETE; READY невозможен.
Initialize при оставшемся непустом наборе сохраняет 409 CHECKS_ALREADY_EXIST при
актуальной версии паспорта. Никакого автоматического дополнения каталога нет.
Формула рисков/интеграций/готовности B2 не меняется; все оставшиеся причины и
acceptedHighRisks сохраняются, acceptanceVerification=UNVERIFIED,
officialGoLiveApproval=false. Бюджет в полном агрегате отсутствует.

Классификация других интеграций, классы/среды паспорта и прочие строки сохраняются.
Все GET остаются read-only и ничего не восстанавливают.

| HTTP | Ответ |
|---|---|
| 400 | BAD_REQUEST / VALIDATION_ERROR, безопасные сообщения без отражения значения |
| 404 | PROJECT_NOT_FOUND, PASSPORT_NOT_FOUND либо COMPONENT/INTEGRATION/CHECK/RISK_NOT_FOUND |
| 409 | PASSPORT/COMPONENT/INTEGRATION/CHECK/RISK_VERSION_CONFLICT; действительная currentVersion и соответствующий versionResource |
| 500 | DATABASE_ERROR, общее безопасное сообщение без SQL, пути, Java-класса и stack trace |

Нового логирования содержимого не добавлено. DELETE паспорта и расширение DELETE
проекта, frontend, схема, миграции, профили datasource в этап не входят.
Автоматические проверки — только на изолированной одноразовой in-memory H2.
Рабочая файловая БД и её копии не открываются.
