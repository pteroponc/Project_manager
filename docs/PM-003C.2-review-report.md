## Реализация

В карточке проекта добавлен вход **«Архитектура и ИБ»**. Отдельное представление
`view=project-architecture&project=…` загружает
`GET /api/projects/{id}/architecture`. Возврат открывает карточку того же проекта;
возврат из неё к реестру сохраняет query, quarter, status, health, attention, sort, direction.
Поддерживаются прямой URL и переходы истории браузера.

Новый `architecture-ui.js` выводит один полученный агрегат в шести разделах:

1. **Сводка** — серверная подпись готовности, все причины с названием связанной записи,
   дата/часовой пояс расчёта, шесть счётчиков состава, ближайшие проверки и все принятые высокие риски.
2. **Паспорт** — пользовательская версия из DTO, критичность, стадия, тип решения, архитектор,
   описание, классы данных, среды, требования, дата пересмотра и UTC-моменты создания/изменения.
3. **Компоненты** — тип, назначение, платформа, критичность, признак внешнего компонента, порядок.
4. **Интеграции** — системы, направление, взаимодействие, категория аутентификации, критичность,
   серверная готовность, собственная классификация, ответственная сторона и комментарий.
5. **Проверки** — тип, обязательность, статус, владелец, план/факт, комментарий/обоснование.
6. **Риски ИБ** — все деловые поля, серверный level, статус и отметка проверки согласования.

Расчёта готовности и матрицы риска в JS нет. Подпись берётся из `assessment.statusLabel`,
уровень — из `risks[].level`; принятые высокие риски и ближайшие проверки — из assessment.
Счётчики состава — длины коллекций одного полученного снимка; это представление данных,
а не повторный расчёт оценки. Никаких дополнительных запросов при переключении разделов нет.
Не подставляются демонстрационные сведения, текущая дата браузера или выдуманные версии.
Неизвестный код обозначается как неизвестный, отсутствующее значение — как отсутствующее.

Готовность не смешивается с health/прогрессом проекта. `officialGoLiveApproval=false`
отображается как отсутствие официального допуска; `UNVERIFIED` — как непроверенное согласование.
UUID, instanceId, технические версии и идентификаторы причин в архитектурном разделе не выводятся.
Идентификаторы используются только для маршрута и сопоставления связанных записей.

Есть отдельные состояния загрузки, ошибки с повтором, 404, отсутствующего паспорта и пустых списков.
При ошибке технический текст ответа не вставляется в страницу. Для отсутствующего паспорта нет
кнопки создания; для пустых проверок нет инициализации — C.2 включает только просмотр.
Доступные действия раздела: возврат, обновление GET и переключение вкладок.

Защита от запоздалых ответов проверяет поколение запроса, текущий проект и активное представление.
Уход из раздела инвалидирует запрос; прежние success/error/finally не меняют новый экран или busy.
Повторное открытие того же проекта тоже получает новое поколение. Ответ с чужим project.id отклоняется.
Также инвалидируются ожидающие запросы старой карточки при уходе с неё.

Текст экранируется до HTML-вставки, переносы строк отображаются через безопасные `<br>`.
Наборы закрытых кодов имеют явные словари с проверкой собственных ключей. Даты без времени
не переводятся через часовой пояс браузера; timestamp паспорта явно выводится в UTC.

Используются существующие классы и стили приложения. Единственное дополнение CSS —
`overflow-wrap:anywhere` для нового представления, чтобы длинный пользовательский текст
не ломал узкий экран. Дизайн рабочего приложения отдельно не перерабатывался.
