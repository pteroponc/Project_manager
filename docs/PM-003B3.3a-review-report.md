## Реализация

| Метод | Маршрут |
|---|---|
| DELETE | `/api/projects/{id}/architecture/components/{recordId}` |
| DELETE | `/api/projects/{id}/architecture/integrations/{recordId}` |
| DELETE | `/api/projects/{id}/architecture/checks/{recordId}` |
| DELETE | `/api/projects/{id}/architecture/risks/{recordId}` |

Обязательны одиночные query-параметры expectedVersion, expectedPassportVersion,
confirmed=true. Отсутствующие/неверные/повторяющиеся/неизвестные параметры — 400
без записей. Контракт и пример: `docs/PM-003B3.3a-child-deletion-api.md`.

Общий сервис работает в одной write-транзакции: validate → ProjectWriteLock →
паспорт PESSIMISTIC_WRITE → целевая запись PESSIMISTIC_WRITE с принадлежностью →
проверка обеих актуальных версий → явное удаление → flush → версия паспорта +1 →
refresh/flush → cardAfterWrite/MANDATORY → полный DTO и пересчёт B2.
Автоматических повторов и последующего GET после commit нет.

Отсутствующие проект/паспорт/запись — 404. Чужая запись не раскрывает версию,
возвращает тот же код, что отсутствующая. Приоритет: сначала наличие/принадлежность,
затем версия паспорта, затем версия записи. 409 содержит реальную currentVersion
и корректный versionResource. Повтор удаления отсутствующей записи — 404, даже
если версия паспорта в запросе уже устарела.

Интеграция использует существующий class writer с пустым набором: явно удаляются
только её `project_integration_data_classes`, выполняется flush, затем удаляется
сама интеграция. Классы других интеграций и паспорта сохраняются. FK NO ACTION,
отсутствие CascadeType.REMOVE/orphanRemoval сохранены.

Успех — 200 с полным агрегатом. Техническая версия паспорта +1 ровно один раз;
версия проекта, createdAt/updatedAt паспорта и documentVersion=1.0 прежние.
Удалённые проверки не восстанавливаются: неполный набор не даёт READY, initialize
при оставшемся наборе даёт 409. Все оставшиеся причины и acceptedHighRisks
сохраняются, UNVERIFIED и officialGoLiveApproval=false; бюджет не возвращается.
Новых логов содержимого и раскрытия SQL/внутренних исключений в ответах нет.

### Покрытие 44 новых тестов

1. Успешное удаление каждого из четырёх типов. Полный ответ равен GET после commit;
   паспорт +1, проект/даты/documentVersion прежние, повторное удаление — безопасный 404.
2. Для каждого типа полные снимки всех полей **12 таблиц** сравниваются до/после:
   единственная разница — целевая строка, её классификация для интеграции и версия
   паспорта. Сохранены другие строки того же типа, другого проекта, классы интеграций
   и паспорта, среды, задачи, контрольные точки, поезда, ID, версии, даты,
   нулевые показатели и максимальный существующий бюджет проектов.
3. Для всех типов: отсутствие родителей/записи, чужая запись (в том числе при
   неверных обеих версиях), устаревшая версия паспорта, устаревшая версия записи.
   Реальные currentVersion/versionResource, снимок без изменений при отказе.
4. Все типы: отсутствие каждого параметра, confirmed=false/TRUE/1/пустое/пробелы,
   неправильные версии/диапазоны, дубликаты/неизвестные параметры — 400 без записи.
5. Для каждого типа ошибка сборки DTO после фактического удаления и flush:
   внутри активной write-транзакции SQL подтверждает отсутствие строки и паспорт=8,
   затем искусственная PersistenceException. После безопасного 500 все 12 таблиц
   полностью совпадают с исходным снимком, включая строку и паспорт=7.
6. Для интеграции дополнительный сбой сразу после удаления классификации и flush:
   классов уже нет, интеграция ещё существует, паспорт ещё version=7. Искусственная
   DataAccess-ошибка откатывает классификацию полностью; интеграция/паспорт прежние.
   Второй тест выше также покрывает сбой после удаления самой интеграции и прироста версии.
7. Удаление проверки из десяти PASSED: READY → NOT_ASSESSED, причины
   CHECK_TYPE_MISSING/CHECKS_INCOMPLETE. Повторные GET ничего не восстанавливают,
   initialize при девяти оставшихся проверках и актуальной версии возвращает 409.
8. Удаление открытого CRITICAL риска убирает только его причину; остаются причина
   HIGH/BLOCKED интеграции и принятый HIGH риск. После удаления интеграции остаются
   ACCEPTED_HIGH_RISK, ATTENTION_REQUIRED и acceptedHighRisks/UNVERIFIED.
9. Write DTO внутри транзакции видит удалённую интеграцию и новый паспорт=8;
   параллельный GET другого соединения видит прежние две интеграции и паспорт=7.
   После commit полный JSON равен возвращённому DTO.
10. Повторные GET карточки/портфеля/обоих impact, другого проекта и проекта без
    паспорта сохраняют все строки/даты/версии. Проверено отсутствие сирот всех
    четырёх типов, классификации интеграций и паспортов.

### Конкурентные сценарии

Все строки таблицы проверены **для каждого из четырёх типов**:

| Сценарий | Фактический результат |
|---|---|
| Два DELETE одной записи | Первый 200, второй ждёт project lock, затем 404; паспорт +1 |
| Два DELETE разных записей, общая версия паспорта | Первый 200, второй ждёт project lock, затем 409 PASSPORT/currentVersion=8; вторая строка сохраняется |
| PATCH первым, DELETE вторым | PATCH 200, DELETE ждёт строку, затем 409 версии записи/currentVersion=4; Winner сохранён, паспорт=7 |
| DELETE первым, PATCH вторым | DELETE 200, PATCH ждёт строку, затем 404; восстановления нет, паспорт=8 |
| DELETE первым, POST компонента вторым | DELETE 200, POST ждёт project lock, затем 409 PASSPORT/currentVersion=8; компонент не создан |
| POST компонента первым, DELETE вторым | POST 201, DELETE ждёт project lock, затем 409 PASSPORT/currentVersion=8; удаляемая строка сохранена |

Используются отдельные соединения/транзакции и CountDownLatch. До освобождения
первой транзакции тест находит реальное ожидание H2 INFORMATION_SCHEMA.SESSIONS:
BLOCKED, BLOCKER_ID и выполняемый SQL ожидаемой таблицы; Future второго запроса
не завершён. Затем отпускается первая транзакция и проверяется итог. Короткий park
только опрашивает состояние; случайных задержек для задания порядка нет.

## Ограничения

Конкурентность проверена на H2 2.3.232, другие СУБД отдельно не удостоверялись.
Уровень доверенного развёртывания и ограничения прежнего полного read-агрегата
сохраняются; новые авторизация/роли и аудит подтверждений не добавлены.
confirmed=true подтверждает явный параметр запроса, не удостоверяет полномочия.
Удаление паспорта и расширение удаления проекта оставлены следующим этапам.

ZIP содержит ровно эти девять файлов с исходными относительными путями, без баз,
копий, логов и сборочных артефактов. Каждый entry сверяется по SHA-256 с исходником.
Работа остановлена для ревью, без коммита и push.
