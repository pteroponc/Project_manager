# Архитектура проекта

## Историческое состояние AS-IS

Историческое описание AS-IS от 14.11.2026 (источник ниже); актуализировано 15.11.2026 в PM-DOC-002. AS-IS baseline: `a1f5b8d6f8b2c8b43c6685c78a52abc2f210f07e` (`codex-dev`).

Источник: принятый архив PM-DOC-001.1, 06-architecture-as-is.md, 12-gaps-and-questions.md. Это краткое описание, не новая архитектура.

Java 21, Spring Boot 3.5.6, Maven, MVC, Bean Validation, JPA/Hibernate, H2. Frontend — статический HTML/CSS/vanilla JS, модули используют общий app state и same-origin API. Слои controller → service → repository. Проект — центральная сущность, портфель и проектная сводка используют связанные сервисы и оценки.

Защита изменений: транзакции, ProjectWriteLock, JPA @Version/CAS в новых контрактах, UUID экземпляра паспорта; legacy PUT имеет ограниченную защиту от устаревших клиентских записей. Два формата ошибок API.

Пилот: отдельный VPS, systemd, Nginx, HTTPS, Basic Auth, UFW, backend loopback, H2 in-memory, отключённая Console. Данные сбрасываются при restart. Обычный локальный профиль отличается от защищённого demo. Инструкции deployment остаются в deploy/demo/.

## Утверждённая целевая архитектура PM-ARCH-001

Владелец утвердил архитектуру и DEC-036 19.11.2026. Ниже описаны целевые компоненты. Их реализация, фактическая схема текущей среды и технические проверки остаются отдельными этапами.

| Компонент | Утверждённое решение |
|---|---|
| Приложение и хранение | Существующий монолит Java/Spring Boot и статический frontend на JavaScript. H2, отдельный защищённый профиль постоянного хранения, сохранение ограничений in-memory demo/smoke. Ручные SQL-миграции, проверяемые backup/restore и защищённый ручной сброс синтетических данных. |
| Управленческое ядро | Ручные операции и подтверждённые предложения ИИ используют общие защищённые сервисы записи. Версии и блокировки защищают от устаревших записей. Версии экземпляра паспорта и набора данных исключают повторное использование старых подтверждений после пересоздания, сброса или восстановления. |
| Источники, наблюдения и история | Неизменяемые версии материалов и извлечённого текста, проверяемые фрагменты, датированные наблюдения с повторным подтверждением неизменных значений, история существенных изменений с прежними/новыми значениями и происхождением. Изменение и запись истории атомарны. |
| Объективные события | Локальный расчёт по подтверждённым изменениям и времени по правилам DEC-036. Устойчивый ключ причины и правила, версии оснований и отдельное ознакомление. Каждая запись истории отмечается обработанной атомарно с событием, повторный проход идемпотентен. Единые определения показателей и согласованный Clock; для сроков используется бизнес-зона Europe/Moscow. |
| Документы | Вставленный текст, TXT, DOCX, PDF с текстовым слоем и XLSX для анализа внешнего документа. Сохранение оригинала, ограниченное локальное извлечение без сети и исполнения активного содержимого, ссылки на страницу/абзац либо лист/ячейки. Загрузка и извлечение не записывают управленческие данные. |
| Помощник | Один заменяемый AI-адаптер с отдельными ограничениями ресурсов и ожидания. Структурированные кандидаты и проверяемые источники, серверная проверка полномочий по [AI_GOVERNANCE.md](03-technical/AI_GOVERNANCE.md). После предпросмотра выбранный разрешённый пакет применяется атомарно через общие сервисы после проверки версий прочитанных данных, с идемпотентностью, фиксацией результата и происхождения. При подтверждении вызов модели не нужен. |
| Базовые отчёты | Независимый сервис проектной и портфельной отчётности из структурированных данных. Предпросмотр, редактирование полного текста, копирование и экспорт итогового DOCX доступны при недоступности адаптера. Запуск, основные разделы и объективные события также независимы от провайдера. |

Импорт Excel, Excel/PDF-экспорт, межпроектный граф, микросервисы, векторная БД и смена frontend-стека исключены. Целевые документы и события добавляются в пределах монолита.

### Оставшиеся технические проверки и условия

- Проверить фактическую конфигурацию H2 и защиту AD-009/010 на конкурентных и устаревших запросах. В затронутых расчётах подтвердить единую семантику AD-002. Долг сохраняет статусы из [ARCHITECTURE_DEBT.md](02-architecture/ARCHITECTURE_DEBT.md).
- Подтвердить изоляцию парсера, ограничение ресурсов, отсутствие незапланированных исходящих обращений, совместимость, лицензии и безопасность библиотек. Численные лимиты и библиотеки в заключении приведены как кандидаты проверки.
- Проверить версии, идемпотентность, восстановление событий, источники и сохранность при отказах. Проверить права ИИ и фактическое состояние данных в негативных сценариях.
- Yandex AI Studio / YandexGPT — первый кандидат испытаний. Реальные вызовы требуют отдельного разрешения на получателя, модель и объём передачи, проверки условий и согласования расходов при необходимости. До внешнего развёртывания выполнить PM-SEC-001 и получить отдельное разрешение на среду.

Последовательность работ — [ROADMAP.md](02-architecture/ROADMAP.md). Критерии приёмки — [ACCEPTANCE.md](04-testing/ACCEPTANCE.md). Заключение и техническая самопроверка Архитектора относятся к проектированию. Функциональные, security- и OFFLINE-проверки имеют статус **NOT VERIFIED**.
