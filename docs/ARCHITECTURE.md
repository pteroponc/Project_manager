# Архитектура AS-IS

Историческое описание AS-IS от 14.11.2026 (источник ниже); актуализировано 15.11.2026 в PM-DOC-002. AS-IS baseline: `a1f5b8d6f8b2c8b43c6685c78a52abc2f210f07e` (`codex-dev`).

Источник: принятый архив PM-DOC-001.1, 06-architecture-as-is.md, 12-gaps-and-questions.md. Это краткое описание, не новая архитектура.

Java 21, Spring Boot 3.5.6, Maven, MVC, Bean Validation, JPA/Hibernate, H2. Frontend — статический HTML/CSS/vanilla JS, модули используют общий app state и same-origin API. Слои controller → service → repository. Проект — центральная сущность, портфель и проектная сводка используют связанные сервисы и оценки.

Защита изменений: транзакции, ProjectWriteLock, JPA @Version/CAS в новых контрактах, UUID экземпляра паспорта; legacy PUT имеет ограниченную защиту от устаревших клиентских записей. Два формата ошибок API.

Пилот: отдельный VPS, systemd, Nginx, HTTPS, Basic Auth, UFW, backend loopback, H2 in-memory, отключённая Console. Данные сбрасываются при restart. Обычный локальный профиль отличается от защищённого demo. Инструкции deployment остаются в deploy/demo/.

## Входные бизнес-требования, не целевая архитектура

Локальный документационный baseline PM-DOC-002: b16e58b2bda128f5204be607228bc2c7d581bbd0. Продуктовые исходники не менялись. DEC-070 задаёт персональный инструмент одного РП, синтетический пилот с реально работающими сценариями, без корпоративной платформы.

Для отдельного анализа: «Мой день» с объективными событиями и независимостью от ИИ (DEC-039/040/046); быстрый и развёрнутый диалог с одним провайдером и текущим контекстом (041/042); новая адаптивная основа (043–045); предложения с основаниями и без дублей (047); простая карточка (048), пять проектов и сквозной сценарий (049); проектная/портфельная отчётность с Word/Excel после ядра (050); готовность по протоколу Комитета и решению РП без новой подсистемы чек-листов (051); исполнение решений (052); актуальность по источнику (053), приоритеты РП (054), первичный Excel-импорт (055); полномочия ИИ — [AI_GOVERNANCE.md](AI_GOVERNANCE.md), DEC-056–058; Hold и завершение по основаниям (063/064); персональные задачи без проекта (065), ручная передача внешних отчётов вместо CMDB-интеграции (066); одна модель проблем (068), история существенных изменений без полных снимков (069).

Исключены: эскалации из пилота (059), CR и Jira-интеграция (060), бюджет (061), подрядчики/договоры/акты/договорные этапы (062), межпроектные связи/граф/каскад/критический путь/автоперепланирование, включая проектирование их перспективной архитектуры сейчас (067). PDF и сложный конструктор отчётов исключены по050. Существование legacy-сущности/поля не включает её в новый scope и не разрешает удалять данные.

## Открытые архитектурные входы

Канонические OQ: [DECISIONS.md](DECISIONS.md). Требуются проверка достаточности истории и доступных сервисов, единая семантика показателей (AD-002), защита используемых мутаций/связей (AD-009/010), раздельные даты и существенная история (AD-003/004), правила актуальности по источнику, пороги сигналов и отсутствие ложной причинности. DEC-068 не подтверждает существование реализованного реестра проблем; прежняя инвентаризация его не обнаружила. Конкретный механизм переиспользования требует проверки.

Открыты: провайдер/условия/разрешение передачи, проверяемые ссылки на источники, отсутствие дублей, подтверждения и повторное применение, вредоносные документы, поддерживаемые форматы, основание возобновления Hold, восстановление синтетического портфеля. DEC-036 остаётся открытым до заключения о технической выполнимости и окончательном объёме реализации. PM-SEC-001 обязателен до следующего внешнего демонстрационного развёртывания.

TO-BE не спроектирована и не утверждена. Не выбираются новая БД, схема хранения/истории, миграции, очереди, провайдер/SDK, инфраструктура, техническая модель полномочий или способы реализации подтверждения. Эта задача лишь передаёт согласованные бизнес-входы в следующий отдельно разрешаемый архитектурный этап. Новых технических проверок продукта/VPS здесь нет.
