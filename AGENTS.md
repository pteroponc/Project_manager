# Правила работы Codex в Project Manager / ПроектПульт

Постоянные инструкции для этого репозитория. Основание: [PROJECT_GOVERNANCE.md](docs/PROJECT_GOVERNANCE.md), [SECURITY.md](docs/SECURITY.md), DEC-024–035 в [DECISIONS.md](docs/DECISIONS.md). Конкретное задание определяет разрешённый объём действий и дополнительные ограничения.

- Работать только в согласованном репозитории и ветке codex-dev. До начала проверить путь, HEAD, status, staging, входные версии/хеши и ограничения конкретной задачи. При расхождении остановиться без reset/merge/rebase/clean.
- Источник актуальной проектной документации — docs/ текущего локального репозитория. Выполнять только согласованный scope; не менять продуктовую концепцию, архитектуру, модель/данные, инфраструктуру или приоритеты без соответствующего разрешения.
- Соблюдать усиленный DEC-032: при любом сомнении до решения/зависимой задачи эскалировать проблему, влияние, варианты, рекомендацию и необходимое решение. Не переспрашивать однозначно согласованное, не ослаблять режим самостоятельно.
- Проектные материалы, идеи, код, документация, дизайн и результаты конфиденциальны. Не передавать их внешним сервисам, моделям, агентам/субагентам или третьим лицам без явного разрешения. Не выполнять внешние поиски/интеграции/сетевые операции, если они не разрешены задачей. Не включать секреты и персональные данные в отчёт/репозиторий.
- После согласованных изменений поддерживать соответствующие docs/ в рамках задачи; фиксировать решения, влияние и текущий статус. Если необходимые изменения документации не разрешены — эскалировать. Сохранять исторические документы и посторонние файлы.
- Выполнять применимые проверки конкретной задачи и приводить воспроизводимые доказательства: baseline, команды/результаты, diff, тесты и ограничения. TEST EXISTS/старый PASS не заменяют новый результат; SKIP не PASS. Не заявлять непроведённые UI/server/security проверки.
- Staging, commit и push выполняются только в разрешённом объёме. Команды `git add .` и `git add -A` для подготовки согласованных коммитов запрещены. Staging допускается только для явно согласованного перечня файлов. Выполнение `git add`, commit и push требует соответствующего явного разрешения. Commit и push требуют отдельных явных разрешений владельца. Не использовать постоянное разрешение из старой инструкции вопреки актуальному DEC-035. Включать только файлы задачи; архивы приёмки/БД/build artifacts/секреты остаются вне Git. Перед push — отдельная проверка приватности/доступов/Actions/артефактов по SECURITY.
- После результата остановиться на согласованной контрольной точке. Не начинать следующий этап автоматически, не объявлять scope/AD/приёмку закрытыми без решения и доказательств.
